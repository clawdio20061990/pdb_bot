# pdb_bot — @palec_do_budki_bot

Telegram-бот-координатор зустрічей (POC). Організатор пише ідею («пиво в Brovarnia в суботу о 19», «басейн у неділю»), бот:

1. розбирає ідею (що / де / коли) — Gemini `gemini-3.6-flash`;
2. робить **один запит до Google Maps на подію**:
   - названий заклад — перевіряє його (якщо назва підходить кільком закладам, показує їх списком і перепитує, який саме; якщо назва ні з чим не збіглася — так і каже);
   - без назви — пропонує до 3 реальних закладів у Гданську **під анкету організатора**;
3. зберігає факти про обраний заклад у події — далі жодних запитів до Maps;
4. показує картку зустрічі: **🚀 надіслати одразу** або **👀 спершу переглянути**;
5. пише кожному персональне запрошення: порівнює збережені факти з анкетою людини й **продає саме її переваги** (що з'їсти, що попити, де тихо), без попереджень про мінуси; потім **перекладає мовою отримувача**;
6. у режимі перегляду — **одне повідомлення зі списком людей**; тиснеш на ім'я й бачиш, чиє запрошення відкрив: ✏️ редагувати вручну, 🤖 змінити інструкцією для AI, 🔄 перегенерувати, 🚫 пропустити, ⬅️ назад;
7. отримувач відповідає ✅ / 🤔 / ❌ (організатору летить сповіщення з підрахунком). Щоб запропонувати інший час чи місце, він просто відповідає реплаєм на запрошення — текст перекладається організатору.

Увесь інтерфейс — мовою з анкети (словники `en`, `pl`, `uk`; інші мови → англійський інтерфейс, але запрошення все одно перекладаються).
До кожного повідомлення додається приписка, що текст створено за допомогою AI (EU AI Act).

## Google Maps і Gemini

- На подію йде рівно один grounded-запит (пошук або перевірка закладу), його результат зберігається в `events.venue_facts` разом із `place_id` і чиститься через 30 днів.
- В запит до Maps ідуть лише план і анкета **організатора** — анкети запрошених туди не передаються.
- Блоки з Maps генеруються одразу мовою читача. Google документує Maps grounding як «лише англійська», але в тестах польська працювала; `GROUNDING_IN_USER_LANGUAGE=false` повертає англійську.
- Потрібен **платний (billing) проєкт Gemini API**: grounding недоступний на free tier, і для користувачів з ЄС умови дозволяють лише Paid Services.
- Умови Gemini API обмежують передачу даних Google Maps іншим користувачам; у цьому POC факти з Maps свідомо використовуються для запрошень — це рішення власника ключа.

## Анкети

`data/users.json` — джерело правди; синхронізується в БД при кожному старті (кого немає у файлі — деактивується).

```json
{ "chat_id": 468603848, "username": "weduy_gorn", "name": "Optional display name", "language": "pl",
  "likes": "wine and beer, board games, …", "dislikes": "noisy places, …" }
```

Щоб додати людину: додай запис → `git push` → Render передеплоїть. Людина має хоч раз натиснути /start у боті (Telegram не дає ботам писати першими). `chat_id` людина може дізнатися, написавши боту будь-що.

## Команди бота

`/start` · `/status` (мої зустрічі й відповіді) · `/profile` · `/cancel` (скасувати введення або незавершену зустріч) · `/whoami`

## Локально

```bash
npm install
cp .env.example .env   # заповнити
npm test               # unit + e2e (вбудований Postgres, фейкові Telegram/Gemini)
npm run try -- "board games on Friday evening"   # живий прогін Gemini на анкетах, без БД і Telegram
npm run migrate        # застосувати міграції до DATABASE_URL + синхронізувати анкети
npm run dev            # long polling — УВАГА: знімає production webhook для цього токена
                       # (краще окремий тестовий бот + Neon branch; або WORKER_ENABLED=false)
```

## Деплой на Render

1. Render Dashboard → **New → Blueprint** → підключити GitHub-репозиторій (для приватного репо дати Render GitHub App доступ до нього).
2. Ввести `BOT_TOKEN`, `GEMINI_API_KEY`, `DATABASE_URL` (Neon pooled URL). `WEBHOOK_SECRET` згенерується сам.
3. **Deploy Blueprint.** При старті бот сам застосує міграції, синхронізує анкети й поставить webhook на `https://<service>.onrender.com/telegram/webhook`.
4. Перед цим вимкни тригер `mainTick` у старому Apps Script, щоб він не конкурував за апдейти.

Free-план засинає після 15 хв без трафіку — перше повідомлення після простою чекає ~1 хв (Telegram повторить доставку). Дані в Neon, тож нічого не губиться.

## Архітектура

```
src/
  index.ts          старт: міграції, анкети, бот, воркер, webhook/polling, graceful shutdown
  server.ts         HTTP: POST /telegram/webhook (secret token), GET /healthz
  bot/handlers.ts   команди, текст, кнопки (усе швидке; повільне — у черзу)
  bot/views.ts      усі повідомлення й клавіатури; блоки Google Maps + джерела
  bot/callbacks.ts  компактні callback_data (≤ 64 байти)
  jobs/queue.ts     черга задач у Postgres (FOR UPDATE SKIP LOCKED, ретраї з backoff)
  jobs/worker.ts    задачі: розбір ідеї, пошук місць, чернетки, переклад, відправка, «що там для мене»
  flows.ts          спільні кроки (картка, чернетки, відправка, звіт)
  ai/gemini.ts      клієнт Gemini Interactions API (fetch, ретраї, цитати Maps)
  ai/pipeline.ts    промпти
  i18n.ts           тексти інтерфейсу en / pl / uk
migrations/         SQL-схема (застосовується автоматично)
```

Усі переходи станів — умовні `UPDATE … WHERE status = …`, тож подвійні натискання, повторна доставка webhook і ретраї задач безпечні.
